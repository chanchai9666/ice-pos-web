# Quickstart & Verification Guide: API Action Loading Overlay

**Feature**: `010-api-action-overlay` | **Date**: 2026-10-25

คู่มือนี้สรุปแนวทางและขั้นตอนในการทดสอบและตรวจสอบการทำงานของ Global Action Loading Overlay ตามเกณฑ์ความสำเร็จ (Success Criteria)

## 1. การเตรียมสภาพแวดล้อม (Prerequisites & Setup)

1. เปิด Terminal และตรวจสอบว่า Dependencies ครบถ้วน:
   ```bash
   npm install
   ```
2. รันแอปพลิเคชันในโหมดพัฒนา:
   ```bash
   npm run dev
   ```
3. เปิดเบราว์เซอร์ไปที่ `http://localhost:3000`

---

## 2. ขั้นตอนการทดสอบตามสถานการณ์ (Validation Scenarios)

### สถานการณ์ที่ 1: การบล็อกหน้าจอขณะทำรายการชำระเงินและบันทึกฟอร์ม (US1 - MVP)
- **ขั้นตอน**:
  1. เข้าสู่ระบบ POS และเลือกสินค้าใส่ตะกร้า 1-2 รายการ
  2. กดปุ่ม "ชำระเงิน" และเลือกวิธีการชำระเงิน (เช่น เงินสด หรือ โอนเงิน)
  3. กดยืนยันการชำระเงิน
- **ผลลัพธ์ที่คาดหวัง**:
  - ทันทีที่กดปุ่ม หน้าจอจะถูกคลุมทับด้วยฉากกั้นกึ่งโปร่งใส (Backdrop) ทันที
  - แสดง Spinner หมุนวนขนาดใหญ่และข้อความภาษาไทย "กำลังประมวลผลการชำระเงิน กรุณารอสักครู่..."
  - ทดลองคลิกเมาส์หรือแตะหน้าจอซ้ำ: ไม่สามารถกดปุ่มใดๆ หรือกระทำการซ้ำซ้อนได้
  - เมื่อ API ตอบกลับสำเร็จ (200 OK): Overlay ปิดตัวลงทันที และแสดงหน้าจอใบเสร็จ/สรุปการขาย

---

### สถานการณ์ที่ 2: การจัดการข้อผิดพลาดและเครือข่ายขัดข้อง (US1 - Error Flow)
- **ขั้นตอน**:
  1. ปิดการเชื่อมต่อเครือข่ายหรือจำลองให้ API คืนสถานะ Error (เช่น HTTP 500 หรือปิด Backend Server)
  2. กดปุ่มทำรายการที่เรียก API
- **ผลลัพธ์ที่คาดหวัง**:
  - Overlay แสดงขึ้นระหว่างรอผล
  - เมื่อได้รับผลตอบกลับข้อผิดพลาด Overlay จะถูกปลดออกทันที
  - แสดงกล่องข้อความแจ้งเตือนข้อผิดพลาดภาษาไทย (Error Dialog) พร้อมปุ่มปิดปลดล็อกหน้าจอ โดยหน้าจอไม่ค้าง

---

### สถานการณ์ที่ 3: คำขอยกเว้นแบบเงียบ (US3 - Silent Background Exemption)
- **ขั้นตอน**:
  1. อยู่ที่หน้าจอขาย POS
  2. จำลองให้ Access Token หมดอายุเพื่อให้ระบบทำงาน Silent Token Refresh ผ่าน `performTokenRefresh()`
- **ผลลัพธ์ที่คาดหวัง**:
  - แคชเชียร์ยังคงสามารถสัมผัสหน้าจอ เลือกสินค้า หรือป้อนตัวเลขได้อย่างต่อเนื่อง
  - ไม่มี Full Blocking Overlay ปรากฏขึ้นมารบกวนการทำงาน
  - คำขอเครือข่ายต่ออายุโทเค็นสำเร็จเบื้องหลัง

---

### สถานการณ์ที่ 4: การตัดการทำงานฉุกเฉินเมื่อหมดเวลา (Timeout Auto-Dismiss)
- **ขั้นตอน**:
  1. จำลอง API ให้ไม่ตอบกลับ (Hang เกิน 15 วินาที สำหรับคำขอทั่วไป หรือ 30 วินาทีสำหรับชำระเงิน)
- **ผลลัพธ์ที่คาดหวัง**:
  - เมื่อครบกำหนดเวลา Overlay จะตัดการทำงาน (Auto-Dismiss) ทันที
  - แสดงกล่องข้อความแจ้งเตือน "การเชื่อมต่อขัดข้องหรือหมดเวลา กรุณาลองใหม่อีกครั้ง"
  - ผู้ใช้สามารถกลับมาควบคุมหน้าจอได้ตามปกติ
