# Feature Specification: ระบบเข้าสู่ระบบสำหรับผู้ใช้งานและแคชเชียร์ (User & Cashier Authentication)

**Feature Branch**: `001-user-login`

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "สร้างหน้า login เข้าระบบ -ส่วนเข้าใช้งานด้วย user / pass -ส่วนเข้าใช้งานด้วย pin"

## Clarifications

### Session 2026-10-21

- Q: เมื่อผู้ใช้งานหรือแคชเชียร์ป้อนรหัสผ่านหรือรหัส PIN ไม่ถูกต้องติดต่อกัน ระบบควรมีนโยบายระงับการลองชั่วคราว (Rate Limiting / Lockout) ที่หน้าจออย่างไร? (FR-012) → A: แสดงตัวเลขนับถอยหลังหน่วงเวลา 60 วินาที เมื่อป้อนผิดติดต่อกัน 5 ครั้ง ก่อนอนุญาตให้ลองใหม่ (Option A)
- Q: หน้าจอเข้าสู่ระบบควรแสดงโหมดใดเป็นค่าเริ่มต้น (Default Mode) เมื่อเปิดใช้งานครั้งแรกบนอุปกรณ์? (FR-002) → A: แสดงโหมด PIN เป็นค่าเริ่มต้นในครั้งแรก และจดจำโหมดล่าสุดที่ผู้ใช้งานเคยเลือกไว้บนอุปกรณ์นั้น (Option A)
- Q: เมื่อแคชเชียร์เข้าสู่ระบบด้วยรหัส PIN สำเร็จ แต่สาขานั้นยังไม่มีกะการทำงานที่เปิดอยู่ (No Active Shift) ระบบควรนำทางผู้ใช้งานไปยังหน้าจอใดเป็นลำดับแรก? (FR-011) → A: นำทางไปยังหน้าจอขายสินค้า (POS) เสมอ แล้วให้หน้าจอขายแสดงข้อความแจ้งเตือนให้เปิดกะเมื่อจะทำรายการ (Option B)
- Q: หน้าจอเข้าสู่ระบบจำเป็นต้องมีปุ่มหรือลิงก์สำหรับสมัครสมาชิก (Self-Registration) หรือกู้คืนรหัสผ่านด้วยตนเอง (Forgot Password) หรือไม่? (Scope Boundaries) → A: ไม่มีปุ่มสมัครสมาชิกหรือรีเซ็ตรหัสผ่านตนเอง (Out of Scope) บัญชีทั้งหมดจัดการโดยผู้ดูแลระบบ (Option A)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - การเข้าสู่ระบบด้วยชื่อผู้ใช้งานและรหัสผ่าน (Priority: P1)

พนักงาน ผู้จัดการสาขา หรือผู้ดูแลระบบ สามารถเข้าสู่ระบบด้วยชื่อผู้ใช้งาน (Username) และรหัสผ่าน (Password) เพื่อเข้าถึงระบบตามระดับสิทธิ์ของตนเองอย่างปลอดภัย

**Why this priority**: เป็นกลไกการยืนยันตัวตนพื้นฐานที่มีความปลอดภัยระดับมาตรฐาน สามารถใช้ได้กับผู้ใช้งานทุกประเภท ไม่ว่าจะเป็นผู้ดูแลระบบ ผู้จัดการ หรือพนักงานทั่วไป

**Independent Test**: สามารถทดสอบได้อย่างสมบูรณ์โดยการกรอกชื่อผู้ใช้งานและรหัสผ่านที่ถูกต้อง แล้วเข้าสู่ระบบสำเร็จเพื่อไปสู่หน้าหลักของระบบตามสิทธิ์ที่ได้รับ

**Acceptance Scenarios**:

1. **Given** ผู้ใช้งานอยู่ที่หน้าเข้าสู่ระบบและเลือกโหมด "เข้าใช้งานด้วยชื่อผู้ใช้ / รหัสผ่าน", **When** กรอก Username และ Password ที่ถูกต้อง แล้วกดปุ่ม "เข้าสู่ระบบ", **Then** ระบบตรวจสอบความถูกต้องสำเร็จ และนำผู้ใช้งานเข้าสู่หน้าจอการทำงานหลักตามสิทธิ์ของตน
2. **Given** ผู้ใช้งานอยู่ที่หน้าเข้าสู่ระบบ, **When** กรอก Username หรือ Password ไม่ถูกต้อง แล้วกดปุ่ม "เข้าสู่ระบบ", **Then** ระบบปฏิเสธการเข้าสู่ระบบและแสดงข้อความแจ้งเตือนที่เข้าใจง่าย โดยไม่ล้างค่า Username ที่กรอกไว้
3. **Given** ผู้ใช้งานไม่ได้กรอก Username หรือ Password, **When** กดปุ่ม "เข้าสู่ระบบ", **Then** ระบบแสดงข้อความแจ้งเตือนให้ระบุข้อมูลในช่องที่เว้นว่างไว้ก่อนดำเนินการส่งข้อมูล

---

### User Story 2 - การเข้าสู่ระบบด่วนด้วยรหัส PIN สำหรับแคชเชียร์ประจำสาขา (Priority: P1)

พนักงานแคชเชียร์หน้าร้านสามารถเลือกสาขาที่ปฏิบัติงาน และป้อนรหัส PIN ตัวเลข 4-8 หลัก (ผ่านแป้นพิมพ์ตัวเลขเสมือนบนหน้าจอสัมผัสหรือคีย์บอร์ดจริง) เพื่อเข้าใช้งานหน้าขายหน้าร้าน (POS) ได้อย่างรวดเร็ว

**Why this priority**: การขายหน้าร้านต้องการความคล่องตัวสูง แคชเชียร์ต้องสามารถสลับกะหรือเปิดหน้าขายได้อย่างรวดเร็วโดยไม่ต้องเสียเวลากรอกรหัสผ่านยาวๆ ทุกครั้ง

**Independent Test**: สามารถทดสอบได้อย่างสมบูรณ์โดยการเลือกสาขาและป้อนรหัส PIN ที่ถูกต้อง จากนั้นระบบยืนยันตัวตนและเข้าสู่หน้าขายหน้าร้านได้ทันที

**Acceptance Scenarios**:

1. **Given** ผู้ใช้งานอยู่ที่หน้าเข้าสู่ระบบและเลือกโหมด "เข้าใช้งานด้วย PIN", **When** เลือกสาขาที่สังกัด และกดป้อนรหัส PIN ที่ถูกต้องครบตามจำนวนหลัก, **Then** ระบบยืนยันตัวตนสำเร็จและนำผู้ใช้งานเข้าสู่หน้าขายหน้าร้าน (POS Terminal) ทันทีเสมอ โดยไม่ขึ้นกับสถานะกะขาย
2. **Given** ผู้ใช้งานอยู่ในโหมดเข้าใช้งานด้วย PIN, **When** หน้าจอปรากฏแผงแป้นตัวเลข (Numpad) บนหน้าจอ, **Then** ผู้ใช้งานสามารถกดปุ่มตัวเลขบนหน้าจอสัมผัส หรือพิมพ์ผ่านคีย์บอร์ดตัวเลขจริงได้เช่นเดียวกัน
3. **Given** ผู้ใช้งานเลือกสาขาแล้ว แต่กรอกรหัส PIN ไม่ถูกต้อง, **When** กดยืนยันหรือป้อนตัวเลขครบ, **Then** ระบบแจ้งเตือนว่ารหัส PIN ไม่ถูกต้อง ล้างช่องตัวเลข PIN และให้โอกาสผู้ใช้งานป้อนใหม่อีกครั้ง
4. **Given** ผู้ใช้งานยังไม่ได้เลือกสาขา, **When** พยายามป้อนรหัส PIN หรือกดยืนยัน, **Then** ระบบแจ้งเตือนให้เลือกสาขาก่อนดำเนินการ

---

### User Story 3 - การสลับโหมดเข้าใช้งานและการจดจำสาขาล่าสุด (Priority: P2)

ผู้ใช้งานสามารถสลับไปมาระหว่างโหมด "ชื่อผู้ใช้ / รหัสผ่าน" และโหมด "รหัส PIN" ได้อย่างสะดวก และระบบสามารถจดจำสาขาล่าสุดที่เคยเลือกไว้บนอุปกรณ์นั้นเพื่อลดขั้นตอนการทำงาน

**Why this priority**: เพิ่มความสะดวกในการใช้งานบนเครื่อง POS ที่ประจำอยู่สาขาเดิม ไม่ต้องเลือกสาขาซ้ำทุกครั้งที่เริ่มงานหรือสลับผู้ใช้

**Independent Test**: ผู้ใช้งานเลือกสลับแท็บ/โหมดแล้วหน้าจอเปลี่ยนรูปแบบการกรอกข้อมูลอย่างถูกต้อง พร้อมทั้งแสดงสาขาที่เคยเลือกไว้โดยอัตโนมัติ

**Acceptance Scenarios**:

1. **Given** ผู้ใช้งานอยู่ที่หน้าเข้าสู่ระบบ, **When** กดสลับไปยังแท็บหรือปุ่มเปลี่ยนโหมดเข้าใช้งาน, **Then** หน้าจอสลับการแสดงผลระหว่างฟอร์ม Username/Password และแผง PIN ทันทีโดยไม่ต้องโหลดหน้าเว็บใหม่
2. **Given** เครื่อง POS เคยมีการเข้าใช้งานด้วย PIN สำเร็จในสาขาใดสาขาหนึ่งมาก่อน, **When** แคชเชียร์เปิดหน้าเข้าสู่ระบบในโหมด PIN ขึ้นมาใหม่, **Then** ระบบเลือกสาขานั้นเป็นค่าเริ่มต้นให้อัตโนมัติ โดยผู้ใช้งานยังคงสามารถเปลี่ยนสาขาได้หากต้องการ
3. **Given** มีการเปิดใช้งานหน้าจอเข้าสู่ระบบเป็นครั้งแรกสุดบนอุปกรณ์ (หรือยังไม่มีข้อมูลบันทึกไว้), **When** หน้าจอโหลดเสร็จสมบูรณ์, **Then** ระบบแสดงผลโหมด PIN เป็นค่าเริ่มต้นทันที และหากมีการสลับโหมด ระบบจะจดจำโหมดล่าสุดไว้ใช้งานในการเปิดครั้งถัดไป

---

### User Story 4 - การรักษาความปลอดภัยและการจัดการข้อผิดพลาด (Priority: P2)

ระบบมีกลไกป้องกันการพยายามสุ่มรหัสผ่านหรือ PIN และแสดงข้อความแจ้งเตือนที่ชัดเจนและปลอดภัยเมื่อเกิดปัญหา

**Why this priority**: ป้องกันการโจมตีหรือการเข้าถึงโดยมิชอบในระบบขายหน้าร้านและข้อมูลการเงิน

**Independent Test**: ทดสอบป้อนรหัสผิดซ้ำๆ และทดสอบเข้าใช้งานด้วยบัญชีที่ถูกระงับ เพื่อตรวจสอบการแจ้งเตือนและการระงับชั่วคราว

**Acceptance Scenarios**:

1. **Given** บัญชีผู้ใช้งานถูกระงับการใช้งานในระบบ, **When** พยายามเข้าสู่ระบบไม่ว่าจะด้วย Username/Password หรือ PIN, **Then** ระบบปฏิเสธการเข้าถึงและแจ้งเตือนว่าบัญชีนี้ถูกระงับ กรุณาติดต่อผู้ดูแลระบบ
2. **Given** มีการป้อนรหัสผ่านหรือรหัส PIN ผิดติดต่อกันครบ 5 ครั้ง, **When** ผู้ใช้งานพยายามเข้าสู่ระบบอีกครั้ง, **Then** ระบบระงับการพยายามเข้าสู่ระบบชั่วคราวเป็นเวลา 60 วินาที พร้อมแสดงข้อความแจ้งเตือนและตัวเลขนับเวลาถอยหลัง (Cooldown) ก่อนอนุญาตให้ลองใหม่

---

### Edge Cases

- **อุปกรณ์ออฟไลน์ชั่วคราวหรือเครือข่ายขัดข้อง**: ระบบต้องแจ้งเตือนอย่างชัดเจนว่าไม่สามารถเชื่อมต่อระบบได้ พร้อมปุ่มให้ลองใหม่อีกครั้ง โดยไม่ทำให้หน้าจอค้าง
- **สาขาไม่มีอยู่ในรายการหรือโหลดรายชื่อสาขาไม่สำเร็จ**: ระบบแสดงข้อความแจ้งเตือนและมีปุ่มให้กดดึงข้อมูลสาขาใหม่อีกครั้ง
- **การป้อนรหัสผ่านหรือ PIN ขณะปิดบังสายตา**: ช่องรหัสผ่านและรหัส PIN ต้องมีการซ่อนตัวอักษรเป็นจุดทึบ (Masking) โดยในส่วนของรหัสผ่านจะมีปุ่มเปิด/ปิดการมองเห็นรหัสผ่าน (Show/Hide Password) เพื่อให้ผู้ใช้งานตรวจสอบความถูกต้องได้
- **การป้อนรหัส PIN เกินหลักหรือป้อนตัวอักษรพิเศษ**: ระบบจำกัดให้รับเฉพาะตัวเลข 0-9 และจำกัดความยาวไม่เกินที่ระบบกำหนด (4-8 หลัก)

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ระบบต้องมีหน้าจอเข้าสู่ระบบที่รองรับ 2 โหมดการยืนยันตัวตน ได้แก่ โหมดชื่อผู้ใช้และรหัสผ่าน (Username & Password) และโหมดรหัส PIN ด่วน (Quick PIN)
- **FR-002**: ระบบต้องแสดงตัวเลือกสำหรับสลับโหมดระหว่าง Username/Password และ PIN ให้เห็นอย่างชัดเจนในหน้าจอเดียวกัน โดยกำหนดให้โหมด PIN เป็นค่าเริ่มต้นเมื่อเปิดใช้งานครั้งแรกบนอุปกรณ์ และจดจำโหมดล่าสุดที่ผู้ใช้งานเคยเลือกไว้
- **FR-003**: ในโหมด Username & Password ระบบต้องมีช่องกรอกชื่อผู้ใช้งาน และช่องกรอกรหัสผ่าน พร้อมปุ่มสลับการมองเห็นรหัสผ่าน (Show/Hide Password)
- **FR-004**: ในโหมด PIN ระบบต้องมีรายการให้ผู้ใช้งานเลือกสาขาที่สังกัด (Branch Selection) และช่องระบุรหัส PIN ตัวเลข
- **FR-005**: ในโหมด PIN ระบบต้องมีแผงแป้นตัวเลขเสมือน (Virtual Numeric Keypad 0-9, ปุ่มลบ, ปุ่มล้าง) บนหน้าจอเพื่ออำนวยความสะดวกแก่อุปกรณ์จอสัมผัส (Touchscreen POS)
- **FR-006**: ระบบต้องรองรับการป้อนข้อมูลรหัส PIN ผ่านคีย์บอร์ดจริงของอุปกรณ์ได้ควบคู่กับแผงแป้นตัวเลขเสมือน
- **FR-007**: ระบบต้องตรวจสอบความถูกต้องของข้อมูลเบื้องต้นก่อนส่งตรวจสอบสิทธิ์ (Client-side Validation) เช่น ตรวจสอบว่าช่องข้อมูลไม่ว่างเปล่า และ PIN เป็นตัวเลขล้วน
- **FR-008**: ระบบต้องบันทึกและจดจำสาขาล่าสุดที่ผู้ใช้งานเคยเลือกเข้าสู่ระบบสำเร็จไว้บนอุปกรณ์ เพื่ออำนวยความสะดวกในการเข้าใช้งานครั้งถัดไป
- **FR-009**: ระบบต้องแสดงสถานะระหว่างกำลังตรวจสอบข้อมูล (Loading State) พร้อมปิดการกดปุ่มซ้ำเพื่อป้องกันการส่งข้อมูลซ้ำซ้อน
- **FR-010**: ระบบต้องแสดงข้อความแจ้งเตือนข้อผิดพลาดเป็นภาษาไทยที่สุภาพ เข้าใจง่าย และไม่เปิดเผยข้อมูลความปลอดภัยภายในระบบ
- **FR-011**: เมื่อเข้าสู่ระบบสำเร็จในโหมด PIN ระบบต้องนำทางผู้ใช้งานไปยังหน้าจอขายสินค้า (POS Terminal) เสมอ (หากยังไม่มีการเปิดกะการทำงาน หน้าจอขายจะแสดงข้อความแจ้งเตือนให้เปิดกะเมื่อจะเริ่มทำรายการ) ส่วนในโหมด Username/Password ให้นำทางไปยังหน้าจอหลักตามระดับสิทธิ์ของผู้ใช้งาน
- **FR-012**: เมื่อมีการป้อนรหัสผ่านหรือรหัส PIN ไม่ถูกต้องติดต่อกันครบ 5 ครั้ง ระบบต้องระงับการลองเข้าสู่ระบบชั่วคราวเป็นเวลา 60 วินาที พร้อมแสดงข้อความแจ้งเตือนและตัวเลขนับเวลาถอยหลัง (Cooldown Timer) ก่อนอนุญาตให้ลองใหม่ได้

### Key Entities *(include if feature involves data)*

- **บัญชีผู้ใช้งาน (User Account)**: ข้อมูลตัวตนของผู้ใช้งาน ประกอบด้วย ชื่อผู้ใช้งาน (Username), ชื่อ-นามสกุลพนักงาน, ระดับสิทธิ์ (Role), สถานะบัญชี (Active/Inactive), และสาขาที่สังกัด
- **สาขา (Branch)**: ข้อมูลสาขาที่เปิดให้บริการ ประกอบด้วย รหัสสาขา, ชื่อสาขา, และสถานะการเปิดให้บริการ
- **เซสชันการเข้าใช้งาน (User Session)**: ข้อมูลการเข้าสู่ระบบที่ได้รับการยืนยันตัวตนแล้ว ประกอบด้วย ข้อมูลผู้ใช้งานที่เข้าสู่ระบบ, สาขาที่ปฏิบัติงาน, เวลาเริ่มต้นเข้าสู่ระบบ, และสิทธิ์การเข้าถึงเมนูต่างๆ
- **ข้อมูลตั้งค่าอุปกรณ์ (Device Preferences)**: ข้อมูลที่บันทึกไว้ในอุปกรณ์ ได้แก่ รหัสสาขาล่าสุดที่เข้าสู่ระบบ และโหมดการเข้าสู่ระบบเริ่มต้น

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: พนักงานแคชเชียร์สามารถเข้าสู่ระบบด้วยโหมด PIN สำเร็จได้ภายในเวลาไม่เกิน 5 วินาที
- **SC-002**: ผู้ใช้งานสามารถเข้าสู่ระบบด้วยโหมด Username & Password สำเร็จได้ภายในเวลาไม่เกิน 15 วินาที
- **SC-003**: 95% ของผู้ใช้งานหน้าร้านสามารถสลับโหมดและเข้าสู่ระบบสำเร็จได้ในครั้งแรกโดยไม่ต้องขอความช่วยเหลือ
- **SC-004**: เมื่อเกิดข้อผิดพลาดในการเข้าสู่ระบบ ผู้ใช้งาน 100% ได้รับข้อความแจ้งเตือนภาษาไทยที่ตรงกับสาเหตุและเข้าใจได้ทันที
- **SC-005**: หน้าจอเข้าสู่ระบบสามารถปรับการแสดงผลและใช้งานได้อย่างราบรื่นทั้งบนหน้าจอแท็บเล็ต หน้าจอ POS สัมผัส และหน้าจอคอมพิวเตอร์ทั่วไป

## Assumptions

- ข้อมูลบัญชีผู้ใช้งาน, รหัสผ่าน, สิทธิ์การใช้งาน, และรหัส PIN ของพนักงานได้รับการลงทะเบียนและกำหนดไว้ล่วงหน้าแล้วในระบบ
- อุปกรณ์ POS มีการเชื่อมต่อเครือข่ายไปยังระบบยืนยันตัวตนกลาง
- อุปกรณ์หน้าร้านอาจเป็นหน้าจอสัมผัสหรือเครื่องคอมพิวเตอร์ตั้งโต๊ะที่มีคีย์บอร์ด จึงต้องรองรับทั้งการสัมผัสและการกดแป้นพิมพ์
- โหมด PIN มุ่งเน้นการใช้งานสำหรับแคชเชียร์และพนักงานหน้าร้านประจำสาขา ส่วนโหมด Username/Password รองรับผู้ใช้งานทุกกลุ่มรวมถึงผู้จัดการและผู้ดูแลระบบ

## Out of Scope (ขอบเขตที่อยู่นอกเหนือการทำงาน)

- การลงทะเบียนผู้ใช้งานใหม่ด้วยตนเอง (Self-Registration) เนื่องจากเป็นระบบปิดภายในองค์กรสำหรับพนักงาน และจัดการผ่านระบบบริหารจัดการผู้ใช้งานส่วนกลาง
- การกู้คืนหรือรีเซ็ตรหัสผ่านด้วยตนเองผ่านช่องทางสาธารณะ (Self-service Password/PIN Reset) การรีเซ็ตรหัสผ่านหรือ PIN กระทำโดยผู้ดูแลระบบหรือผู้จัดการสาขาเท่านั้น
