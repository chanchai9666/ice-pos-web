# Quickstart & Verification Guide: Token Refresh & Session Timeout

**Branch**: `008-auth-token-refresh`  
**Feature**: `specs/008-auth-token-refresh/spec.md`  

คู่มือทดสอบและตรวจสอบการทำงานของฟีเจอร์การต่ออายุ Token อัตโนมัติและการนำทางออกจากระบบเมื่อหมดเวลา

รันคำสั่งตรวจสอบ Type Strict Check และ Linting ในโปรเจกต์:

npx tsc --noEmit

# 2. ตรวจสอบ Linting และมาตรฐานโค้ด
npm run lint

## 2. สถานการณ์การทดสอบการใช้งานจริง (Manual Verification Scenarios)

### สถานการณ์ที่ 1: การต่ออายุ Token เบื้องหลังอัตโนมัติขณะใช้งานต่อเนื่อง (Silent Token Refresh)

1. **เตรียมการ**:
   - เข้าสู่ระบบ POS ด้วย PIN หรือชื่อผู้ใช้และรหัสผ่านตามปกติ
   - เปิดหน้าต่าง Developer Tools (F12) ไปที่แท็บ **Console** และ **Application -> Local Storage**
2. **การทดสอบ**:
   - ใน Developer Console แก้ไข `ice_pos_access_token` ให้เป็นค่าที่ไม่ถูกต้องหรือสตริงหมดอายุ (เช่น `'invalid_token_test'`) โดยยังคงปล่อยให้ `ice_pos_refresh_token` เป็นค่าเดิมที่ถูกต้อง
   - บนหน้าจอ POS ให้คลิกเลือกสินค้าหรือทำการค้นหาสินค้า (ซึ่งจะทำให้เกิดการเรียก API เช่น ดึงสต็อกหรือแคตตาล็อก)
3. **ผลลัพธ์ที่คาดหวัง**:
   - คำขอแรกจะตอบกลับ 401 Unauthorized
   - ระบบตรวจพบ 401 และทำการเรียก `POST /api/v1/auth/refresh` เบื้องหลังโดยอัตโนมัติ
   - Local Storage ได้รับ Access Token ชุดใหม่ที่ใช้งานได้
   - คำขอเดิมได้รับการส่งซ้ำ (Retry) สำเร็จ หน้าจอ POS แสดงผลลัพธ์สินค้าตามปกติ ไม่มีการสะดุด ไม่มีการเด้งออกจากระบบ และไม่มีหน้าจอหมุนค้าง

---

### สถานการณ์ที่ 2: การป้องกันและรวมคำขอพร้อมกัน (Concurrent Requests During Refresh)

1. **การทดสอบ**:
   - จำลอง Access Token หมดอายุเหมือนสถานการณ์ที่ 1
   - ทำการกดเปลี่ยนหมวดหมู่สินค้าอย่างรวดเร็ว 2-3 ครั้งติดต่อกัน (ทำให้เกิดคำขอ API พร้อมกันหลายตัว)
2. **ผลลัพธ์ที่คาดหวัง**:
   - ในแท็บ Network จะพบการเรียก `POST /api/v1/auth/refresh` เพียง **1 ครั้งเท่านั้น**
   - ทุกคำขอที่รออยู่จะได้รับ Token ใหม่ชุดเดียวกันและทำงานสำเร็จทั้งหมดพร้อมกันอย่างถูกต้อง

---

### สถานการณ์ที่ 3: การนำทางออกจากระบบเมื่อ Refresh Token หมดอายุ (Expired Session Auto-Logout)

1. **เตรียมการ**:
   - มีสินค้าอย่างน้อย 1 รายการอยู่ในตะกร้าขาย POS
   - ใน Developer Tools ปรับค่า `ice_pos_refresh_token` ให้เป็นค่าที่หมดอายุหรือไม่ถูกต้อง
2. **การทดสอบ**:
   - ทำการคลิกเลือกสินค้าหรือเรียก API
3. **ผลลัพธ์ที่คาดหวัง**:
   - การเรียก Refresh Token ล้มเหลว (401)
   - ระบบทำการล้าง `ice_pos_access_token` และ `ice_pos_refresh_token` ออกจาก Local Storage
   - ข้อมูลสินค้าในตะกร้าและข้อมูลสาขายังคงอยู่ ไม่สูญหาย
   - มี Toast Notification สีเหลือง/แดง แสดงข้อความ: **"เซสชันการใช้งานหมดอายุ กรุณาเข้าสู่ระบบใหม่อีกครั้ง"**
   - หน้าจอถูกนำทางกลับไปยังหน้า `/login` ทันที
   - เมื่อกดเลือกแท็บ PIN Login ชื่อสาขาเดิมจะถูกเลือกไว้ให้โดยอัตโนมัติ แคชเชียร์เพียงแค่ใส่ PIN เพื่อเข้าสู่ระบบกลับมาทำงานต่อได้ทันที
