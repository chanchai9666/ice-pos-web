# Feature Specification: การต่ออายุเซสชันอัตโนมัติขณะใช้งานและการออกจากระบบเมื่อหมดเวลาการใช้งาน (Continuous Usage Token Refresh & Idle Session Timeout)

**Feature Branch**: `008-auth-token-refresh`

**Created**: 2026-10-24

**Status**: Draft

**Input**: User description: "-เพิ่มส่วนการ refresh token หากมีการใช้งานต่อเนื่อง\n-หากไม่ได้ใช้งานนานแล้วไม่สามารถ refresh token ได้ให้ทำการเด้งออกจากระบบเพื่อให้เข้าใช้งานใหม่"

## Clarifications

### Session 2026-10-24

- Q: ระบบควรกำหนดระยะเวลาที่ไม่มีการใช้งาน (Idle/Inactivity Timeout) ก่อนที่จะทำการนำทางออกจากระบบ (Auto Logout) ไว้นานเท่าใด? → A: ไม่อิงเวลาในหน้าเว็บ ให้ตัดออกจากระบบเฉพาะเมื่อ Refresh Token จาก API หมดอายุจริงหรือไม่สามารถต่ออายุได้เท่านั้น
- Q: เมื่อเซสชันหมดอายุและระบบนำทางออกจากระบบ ข้อมูลรายการสินค้าในตะกร้าขาย (Cart Items) ที่ค้างอยู่บนหน้าจอ POS ควรได้รับการจัดการอย่างไร? → A: คงรายการสินค้าในตะกร้าไว้ เพื่อให้แคชเชียร์ใส่ PIN กลับเข้ามาทำรายการขายต่อได้ทันที

## User Scenarios & Testing *(mandatory)*

### User Story 1 - การต่ออายุเซสชันการใช้งานอย่างต่อเนื่องโดยอัตโนมัติ (Continuous Usage Automatic Session Refresh) (Priority: P1)

แคชเชียร์และผู้ใช้งานที่กำลังปฏิบัติงานหน้าร้านอย่างต่อเนื่อง สามารถใช้งานระบบ POS ได้โดยไม่มีการสะดุดหรือถูกตัดออกจากระบบกลางคัน เมื่อเซสชันหรือสิทธิ์เข้าถึงใกล้หมดอายุ ระบบจะทำการต่ออายุเซสชันเบื้องหลังโดยอัตโนมัติ ทำให้ผู้ใช้สามารถขายสินค้า ค้นหาสินค้า สแกนบาร์โค้ด และรับชำระเงินได้อย่างต่อเนื่องราบรื่น

**Why this priority**: การตัดเซสชันขณะที่แคชเชียร์กำลังคิดเงินหรือให้บริการลูกค้าหน้าร้านสร้างผลกระทบต่อความพึงพอใจของลูกค้าและขัดขวางกระบวนการขาย การต่ออายุอัตโนมัติช่วยให้ธุรกิจดำเนินไปได้อย่างไม่ติดขัด

**Independent Test**: เข้าสู่ระบบ POS และจำลองการปฏิบัติงานขายอย่างต่อเนื่อง เมื่อเวลาผ่านไปจนถึงรอบการหมดอายุของสิทธิ์เดิม ระบบต้องต่ออายุเซสชันเบื้องหลังสำเร็จ โดยแคชเชียร์ยังคงสามารถยิงบาร์โค้ดและทำรายการขายได้ตามปกติโดยไม่มีหน้าต่างหลุดออกจากระบบ

**Acceptance Scenarios**:

1. **Given** แคชเชียร์เข้าสู่ระบบและกำลังปฏิบัติงานในหน้าจอ POS อย่างต่อเนื่อง, **When** สิทธิ์การเข้าถึงใกล้หมดอายุหรือหมดอายุระหว่างการใช้งาน, **Then** ระบบทำการต่ออายุสิทธิ์เข้าถึง (Token Refresh) ในเบื้องหลังโดยอัตโนมัติโดยที่ผู้ใช้ไม่ต้องดำเนินการใดๆ เพิ่มเติม
2. **Given** มีการส่งคำขอไปยังระบบขณะที่สิทธิ์การเข้าถึงเดิมหมดอายุพอดี, **When** ระบบได้รับการแจ้งเตือนสิทธิ์หมดอายุ, **Then** ระบบจะทำการต่ออายุสิทธิ์ใหม่และส่งคำขอเดิมซ้ำให้อัตโนมัติในทันที ทำให้รายการไม่ล้มเหลว
3. **Given** แคชเชียร์กำลังพิมพ์หรือเลือกรายการสินค้า, **When** ระบบทำการต่ออายุเซสชันเบื้องหลัง, **Then** หน้าจอการทำงานไม่มีการกระตุก ไม่มีการรีโหลดหน้าจอใหม่ และไม่มีการแสดงหน้าต่างที่บล็อกการทำงานของผู้ใช้

### User Story 2 - การนำทางออกจากระบบเมื่อเซสชันหมดอายุเนื่องจากไม่มีการใช้งานนาน (Idle Session Expiration & Auto Logout) (Priority: P1)

เมื่ออุปกรณ์ POS ถูกปล่อยทิ้งไว้โดยไม่มีการใช้งานเป็นเวลานานจนสิทธิ์การต่ออายุหมดอายุ หรือเซิร์ฟเวอร์ปฏิเสธการต่ออายุเซสชัน ระบบจะทำการนำทางออกจากระบบ (Auto Logout) โดยอัตโนมัติ พร้อมล้างสิทธิ์การเข้าถึงออกจากเครื่อง เพื่อความปลอดภัยของข้อมูล ป้องกันไม่ให้ผู้อื่นมาสวมสิทธิ์ทำรายการขาย และนำทางผู้ใช้กลับไปยังหน้าจอเข้าสู่ระบบ

**Why this priority**: ป้องกันความเสี่ยงด้านความปลอดภัยเมื่อแคชเชียร์ลืมออกจากระบบหรือละทิ้งหน้าจอ POS ไว้เป็นเวลานาน เพื่อให้สอดคล้องกับมาตรฐานความปลอดภัยของระบบขายหน้าร้าน

**Independent Test**: เข้าสู่ระบบ POS แล้วปล่อยเครื่องทิ้งไว้โดยไม่มีการสัมผัสหรือทำรายการจนกระทั่งเซสชันหมดอายุและไม่สามารถต่ออายุได้ ตรวจสอบว่าระบบนำทางออกจากระบบและกลับสู่หน้าจอเข้าสู่ระบบอย่างถูกต้อง

**Acceptance Scenarios**:

1. **Given** ผู้ใช้งานเข้าสู่ระบบไว้ แต่ไม่มีการสัมผัส แตะหน้าจอ หรือทำรายการใดๆ เป็นเวลานานจนสิทธิ์ต่ออายุหมดอายุ, **When** ระบบตรวจพบว่าเซสชันหมดอายุและไม่สามารถต่ออายุได้, **Then** ระบบจะยุติเซสชัน ล้างข้อมูลสิทธิ์ออกจากเครื่อง และนำทางกลับไปยังหน้าจอเข้าสู่ระบบโดยอัตโนมัติ
2. **Given** ระบบพยายามต่ออายุสิทธิ์แต่เซิร์ฟเวอร์ปฏิเสธ (เช่น สิทธิ์ถูกเพิกถอน หรือเซสชันหมดอายุถาวร), **When** เกิดข้อผิดพลาดในการต่ออายุ, **Then** ระบบจะดำเนินการออกจากระบบทันที ไม่ปล่อยให้หน้าจอค้างอยู่ในสถานะที่ใช้งานไม่ได้

### User Story 3 - การแจ้งเตือนที่เข้าใจง่ายและการนำทางกลับสู่หน้าจอเข้าสู่ระบบ (Clear Notification & Graceful Redirect) (Priority: P2)

เมื่อเกิดกรณีเซสชันหมดอายุและถูกเด้งออกจากระบบ ระบบจะแสดงข้อความแจ้งเตือนภาษาไทยที่กระชับ ชัดเจน (เช่น "เซสชันการใช้งานหมดอายุ กรุณาเข้าสู่ระบบใหม่อีกครั้ง") พร้อมนำทางกลับไปยังหน้าจอเข้าสู่ระบบ โดยคงข้อมูลสาขาล่าสุดไว้ เพื่อให้แคชเชียร์สามารถป้อนรหัส PIN หรือรหัสผ่านเพื่อเข้าใช้งานต่อได้อย่างรวดเร็ว

**Why this priority**: การแจ้งเตือนที่ชัดเจนช่วยให้ผู้สูงอายุและแคชเชียร์เข้าใจทันทีว่าเกิดอะไรขึ้นโดยไม่ตกใจ พร้อมให้ช่องทางเข้าสู่ระบบกลับมาทำงานต่อได้อย่างสะดวก

**Independent Test**: ปล่อยให้เซสชันหมดอายุ ตรวจสอบว่ามีข้อความแจ้งเตือนที่อ่านง่ายปรากฏขึ้น และหน้าจอเข้าสู่ระบบยังคงจำสาขาเดิมไว้ ทำให้สามารถกด PIN เข้าสู่ระบบต่อได้ทันที

**Acceptance Scenarios**:

1. **Given** ผู้ใช้ถูกนำทางออกจากระบบเนื่องจากเซสชันหมดอายุ, **When** หน้าจอเปลี่ยนไปยังหน้าเข้าสู่ระบบ, **Then** ระบบแสดงข้อความแจ้งเตือนภาษาไทยอย่างชัดเจนว่า "เซสชันการใช้งานหมดอายุ กรุณาเข้าสู่ระบบใหม่อีกครั้ง"
2. **Given** แคชเชียร์กลับมายังหน้าจอเข้าสู่ระบบหลังจากเซสชันหมดอายุ, **When** เข้าสู่หน้าจอ PIN Login, **Then** สาขาล่าสุดที่เลือกไว้ยังคงถูกเลือกอยู่ ทำให้แคชเชียร์เพียงแค่ใส่ PIN เพื่อเข้าทำงานต่อได้ทันที

---

### Edge Cases

- **กรณีขาดการเชื่อมต่ออินเทอร์เน็ตชั่วคราวขณะพยายามต่ออายุสิทธิ์**: หากอุปกรณ์ออฟไลน์ชั่วคราว ระบบต้องไม่เด้งออกจากระบบทันทีในเสี้ยววินาที แต่ให้รอการตรวจสอบสถานะเครือข่าย หรือแสดงแจ้งเตือนปัญหาเครือข่ายก่อนตัดสินใจออกจากระบบเมื่อยืนยันว่าเซสชันไม่ถูกต้อง
- **กรณีมีการส่งคำขอพร้อมกันหลายรายการขณะสิทธิ์หมดอายุ (Concurrent Requests)**: ระบบต้องรวมการขอต่ออายุสิทธิ์เป็นคำขอเดียว (Single Refresh Request) ไม่ส่งคำขอต่ออายุซ้ำซ้อนกันหลายครั้งพร้อมกัน
- **กรณีมีสินค้าค้างอยู่ในตะกร้าขายก่อนเซสชันหมดอายุ**: ระบบต้องคงรายการสินค้าในตะกร้าไว้ ไม่ล้างทิ้ง เพื่อให้แคชเชียร์คนเดิมสามารถใส่รหัส PIN กลับเข้ามาและขายสินค้าต่อได้ทันทีโดยไม่ต้องเริ่มต้นยิงบาร์โค้ดใหม่ทั้งหมด

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ระบบต้องตรวจจับความเคลื่อนไหวของผู้ใช้งานและทำการต่ออายุเซสชัน (Token Refresh) เบื้องหลังโดยอัตโนมัติเมื่อมีการใช้งานต่อเนื่อง
- **FR-002**: การต่ออายุเซสชันเบื้องหลังต้องไม่รบกวนการทำงานบนหน้าจอ ไม่แสดงหน้าต่างโหลดที่ขัดจังหวะการกดปุ่ม และไม่ทำให้ข้อมูลที่กำลังกรอกสูญหาย
- **FR-003**: เมื่อคำขอเรียกข้อมูลได้รับแจ้งว่าสิทธิ์เดิมหมดอายุ ระบบต้องดำเนินการขอต่ออายุสิทธิ์ใหม่และส่งคำขอนั้นซ้ำให้โดยอัตโนมัติอย่างราบรื่น (Silent Retry)
- **FR-004**: เมื่อมีการส่งคำขอหลายรายการพร้อมกันขณะสิทธิ์หมดอายุ ระบบต้องจัดการให้มีการขอต่ออายุสิทธิ์เพียงครั้งเดียว และให้ทุกคำขอที่รออยู่ใช้สิทธิ์ใหม่ร่วมกัน
- **FR-005**: ระบบต้องตัดการเชื่อมต่อและยุติเซสชัน (Auto Logout) ในทันที เมื่อเซิร์ฟเวอร์ปฏิเสธการต่ออายุสิทธิ์หรือ Refresh Token หมดอายุจริง โดยไม่อิงเวลาจับเวลา Inactivity แยกต่างหากบนหน้าเว็บ
- **FR-006**: เมื่อระบบทำการยุติเซสชันอัตโนมัติ ระบบต้องล้างข้อมูลสิทธิ์การเข้าถึงออกจากหน่วยความจำและหน่วยจัดเก็บข้อมูลของเครื่องอย่างปลอดภัย
- **FR-007**: ระบบต้องนำทางผู้ใช้กลับไปยังหน้าจอเข้าสู่ระบบ พร้อมแสดงข้อความแจ้งเตือนภาษาไทยที่กระชับและเข้าใจง่าย เช่น "เซสชันการใช้งานหมดอายุ กรุณาเข้าสู่ระบบใหม่อีกครั้ง"
- **FR-008**: ระบบต้องจดจำข้อมูลสาขาที่ใช้งานล่าสุดไว้ เพื่อให้แคชเชียร์สามารถเข้าสู่ระบบด้วยรหัส PIN ได้ทันทีโดยไม่ต้องค้นหาสาขาใหม่
- **FR-009**: ข้อความแจ้งเตือนและองค์ประกอบบนหน้าจอต้องเป็นไปตามมาตรฐาน Elderly-Friendly มีขนาดตัวอักษรไม่เล็กกว่า 16px และมีคอนทราสต์ชัดเจนตามเกณฑ์ WCAG 2.1 AA
- **FR-010**: ระบบต้องคงรายการสินค้าในตะกร้าขาย (Cart Items) ไว้เมื่อมีการเด้งออกจากระบบ เพื่ออำนวยความสะดวกให้แคชเชียร์สามารถเข้าสู่ระบบและทำรายการขายต่อได้ทันที

### Key Entities *(include if feature involves data)*

- **Session Context**: สถานะการเข้าสู่ระบบของผู้ใช้งาน ประกอบด้วย สิทธิ์การเข้าถึง (Access Token), สิทธิ์สำหรับการต่ออายุ (Refresh Token), ข้อมูลผู้ใช้, และข้อมูลสาขาปัจจุบัน
- **Session Lifecycle Status**: สถานะวงจรชีวิตของเซสชัน เช่น `ACTIVE` (กำลังใช้งาน), `REFRESHING` (กำลังต่ออายุสิทธิ์เบื้องหลัง), และ `EXPIRED` (หมดอายุและต้องเข้าสู่ระบบใหม่)
- **Inactivity Monitor**: กลไกตรวจสอบระยะเวลาที่ไม่มีการโต้ตอบของผู้ใช้ เพื่อประเมินความปลอดภัยและการหมดเวลาของเซสชัน

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: แคชเชียร์ที่ปฏิบัติงานต่อเนื่องสามารถทำงานได้ตลอดทั้งกะโดยไม่พบการหลุดออกจากระบบกะทันหันอันเนื่องมาจากการหมดอายุของเซสชัน (0 Unexpected Logouts during active usage)
- **SC-002**: 100% ของกรณีที่ระบบถูกปล่อยทิ้งไว้จนเซสชันหมดอายุและไม่สามารถต่ออายุได้ ระบบจะนำทางออกจากระบบและกลับสู่หน้าล็อกอินอย่างปลอดภัย
- **SC-003**: 100% ของคำขอที่เกิดสิทธิ์หมดอายุระหว่างใช้งานต่อเนื่อง ได้รับการต่ออายุสิทธิ์และทำรายการสำเร็จโดยที่ผู้ใช้ไม่ต้องกดทำรายการซ้ำ
- **SC-004**: ผู้ใช้รับทราบสาเหตุการออกจากระบบผ่านข้อความแจ้งเตือนที่เข้าใจง่ายภายใน 1 วินาทีหลังการเปลี่ยนหน้าจอ
- **SC-005**: แคชเชียร์สามารถกลับเข้าสู่ระบบหลังจากเซสชันหมดอายุได้รวดเร็วภายในเวลาไม่เกิน 5 วินาที โดยไม่ต้องเลือกสาขาใหม่

## Assumptions

- ระบบเซิร์ฟเวอร์ Backend มี API Endpoint สำหรับการต่ออายุสิทธิ์ (`/api/v1/auth/refresh`) รองรับอยู่แล้ว
- นโยบายระยะเวลาอายุของสิทธิ์การเข้าถึงและสิทธิ์การต่ออายุถูกกำหนดและควบคุมโดยเซิร์ฟเวอร์
- แคชเชียร์ทำงานบนอุปกรณ์หลักประจำสาขา ซึ่งระบบจัดเก็บข้อมูลสาขาล่าสุดไว้ในเครื่องเพื่อความสะดวกรวดเร็ว
