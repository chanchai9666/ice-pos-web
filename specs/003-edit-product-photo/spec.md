# Feature Specification: การแก้ไขข้อมูลสินค้า - ถ่ายภาพโดยตรงและแสดงผลในหน้ารายการทันที (Product Edit: Direct Camera Photo Capture & Instant List Image Display)

**Feature Branch**: `003-edit-product-photo`

**Created**: 2026-10-21

**Status**: Draft

**Input**: User description: "ส่วนการแก้ไขข้อมูลสินค้า -เพิ่มแนบรูปจากการถ่ายภาพโดยตรง -รูปภาพต้องแสดงในหน้า list ด้วยโดยไม่ต้อง รีเฟชหน้าเอง"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ถ่ายภาพสินค้าจากกล้องของอุปกรณ์โดยตรงในหน้าแก้ไขข้อมูลสินค้า (Priority: P1)

ในฐานะผู้จัดการร้านหรือผู้ดูแลระบบที่กำลังแก้ไขข้อมูลสินค้า
ฉันต้องการเปิดกล้องบนอุปกรณ์ (เช่น แท็บเล็ต POS, มือถือ หรือคอมพิวเตอร์ที่มีกล้อง/เว็บแคม) แล้วกดถ่ายภาพสินค้าเพื่อนำมาใช้เป็นภาพประจำตัวสินค้าได้ทันที
เพื่อความสะดวกรวดเร็วในการอัปเดตภาพสินค้าหน้าร้านจริง โดยไม่ต้องเสียเวลาถ่ายจากแอปพลิเคชันอื่นแล้วค่อยค้นหาไฟล์มาอัปโหลด

**Why this priority**:
เป็นความต้องการหลักข้อแรกของผู้ใช้ การถ่ายภาพโดยตรงช่วยลดขั้นตอนการทำงานของพนักงานหน้าร้านอย่างมาก โดยเฉพาะในร้านค้าที่มีการเพิ่มหรืออัปเดตสินค้าใหม่หน้าร้านเป็นประจำ

**Independent Test**:
ผู้ใช้สามารถกดปุ่ม "ถ่ายภาพด้วยกล้อง" ภายในแบบฟอร์มแก้ไขสินค้า ระบบเปิดหน้าจอมองภาพจากกล้อง (Camera Viewfinder) ผู้ใช้กดปุ่มชัตเตอร์เพื่อจับภาพ จากนั้นเห็นภาพตัวอย่างที่ถ่าย และสามารถเลือก "ใช้ภาพนี้" หรือ "ถ่ายใหม่" ได้ เมื่อกดยืนยัน ภาพที่ถ่ายจะปรากฏในช่องรูปภาพสินค้าพร้อมบันทึก

**Acceptance Scenarios**:

1. **เปิดกล้องถ่ายภาพ**: **Given** ผู้ใช้อยู่ในหน้าต่างแก้ไขข้อมูลสินค้า, **When** ผู้ใช้กดปุ่ม "ถ่ายภาพด้วยกล้อง", **Then** ระบบร้องขอสิทธิ์การเข้าถึงกล้อง (หากยังไม่เคยอนุญาต) และแสดงหน้าต่างถ่ายภาพพร้อมภาพเคลื่อนไหวสดจากกล้อง (Live Preview)
2. **กดชัตเตอร์จับภาพ**: **Given** หน้าต่างกล้องเปิดอยู่และแสดงภาพสด, **When** ผู้ใช้กดปุ่มถ่ายภาพ (ปุ่มชัตเตอร์ขนาดใหญ่), **Then** ระบบจับภาพนิ่งและแสดงผลตัวอย่างภาพที่ถ่ายทันที พร้อมปุ่ม "ถ่ายใหม่" และ "ใช้ภาพนี้"
3. **ถ่ายใหม่เมื่อภาพไม่ชัด**: **Given** ระบบแสดงภาพตัวอย่างที่เพิ่งถ่าย, **When** ผู้ใช้กดปุ่ม "ถ่ายใหม่", **Then** ระบบจะลบภาพตัวอย่างนั้นและกลับเข้าสู่หน้าจอแสดงภาพสดจากกล้องอีกครั้ง
4. **ยืนยันการใช้ภาพที่ถ่าย**: **Given** ระบบแสดงภาพตัวอย่างที่เพิ่งถ่าย, **When** ผู้ใช้กดปุ่ม "ใช้ภาพนี้", **Then** ภาพจะถูกนำไปแสดงเป็นภาพตัวอย่างในแบบฟอร์มแก้ไขสินค้า และปิดหน้าต่างถ่ายภาพอัตโนมัติ

---

### User Story 2 - แสดงภาพสินค้าที่อัปเดตใหม่ในตารางรายการสินค้าทันทีโดยไม่ต้องรีเฟรชหน้าเว็บ (Priority: P1)

ในฐานะผู้จัดการร้านหรือแคชเชียร์ที่แก้ไขข้อมูลสินค้าและอัปเดตภาพถ่ายสินค้าเรียบร้อยแล้ว
ฉันต้องการเห็นภาพสินค้าใหม่แสดงในตารางรายการสินค้า (Product Catalog List) ทันทีหลังจากบันทึกสำเร็จ
โดยไม่ต้องกดรีเฟรชเบราว์เซอร์ (F5 หรือ Reload Page) เอง
เพื่อความต่อเนื่องในการทำงานและความมั่นใจว่าข้อมูลและภาพถ่ายได้รับการบันทึกลงสู่ระบบเรียบร้อยแล้ว

**Why this priority**:
เป็นความต้องการหลักข้อที่สองที่ส่งผลโดยตรงต่อประสบการณ์การใช้งาน (UX) หากบันทึกแล้วภาพในรายการยังเป็นภาพเดิมหรือไม่แสดง ผู้ใช้จะเกิดความสับสนและคิดว่าระบบทำงานผิดพลาด การแสดงผลทันทีแบบ Real-time ช่วยสร้างความมั่นใจและลดภาระการรีเฟรชหน้าจอ

**Independent Test**:
เปิดหน้ารายการสินค้า เลือกสินค้าตัวใดตัวหนึ่งเพื่อแก้ไข แล้วเปลี่ยนภาพสินค้า (ผ่านการถ่ายภาพหรืออัปโหลด) จากนั้นกดปุ่ม "บันทึกการแก้ไข" เมื่อหน้าต่างแก้ไขปิดลง แถวของสินค้าดังกล่าวในตารางรายการสินค้าจะต้องแสดงรูปภาพใหม่ที่เพิ่งบันทึกทันทีโดยไม่มีการโหลดหน้าเว็บใหม่ทั้งหมด

**Acceptance Scenarios**:

1. **อัปเดตภาพในตารางทันทีหลังบันทึก**: **Given** สินค้ามีรูปภาพเดิมหรือไม่มีรูปภาพ, **When** ผู้ใช้แก้ไขสินค้าโดยถ่ายภาพใหม่และกด "บันทึกการแก้ไข" สำเร็จ, **Then** หน้าต่างแก้ไขปิดลง และช่องรูปภาพของสินค้านั้นในตารางรายการจะเปลี่ยนเป็นรูปภาพใหม่ทันที
2. **ป้องกันปัญหาภาพเก่าค้างในหน่วยความจำแคช**: **Given** ผู้ใช้อัปเดตรูปภาพสินค้าเดิมด้วยภาพใหม่, **When** บันทึกข้อมูลสำเร็จและตารางแสดงผล, **Then** รูปภาพที่แสดงต้องเป็นรูปภาพล่าสุดจริง ไม่ติดแคชภาพเก่าของเบราว์เซอร์
3. **รักษาตำแหน่งการนำทางและตัวกรองเดิม**: **Given** ผู้ใช้อยู่ในตารางหน้าที่ 2 หรือกำลังค้นหา/กรองหมวดหมู่สินค้าอยู่, **When** แก้ไขรูปภาพสินค้าสำเร็จ, **Then** ตารางยังคงอยู่ที่หน้าเดิม ตัวกรองเดิม และสินค้าที่เพิ่งแก้ไขแสดงภาพใหม่อย่างถูกต้อง

### User Story 3 - การควบคุมอุปกรณ์กล้องและทางเลือกการนำเข้ารูปภาพ (Priority: P2)

ในฐานะผู้ใช้งานบนอุปกรณ์ที่มีกล้องมากกว่า 1 ตัว (เช่น แท็บเล็ตหรือสมาร์ตโฟนที่มีกล้องหน้าและกล้องหลัง)
ฉันต้องการสลับกล้องระหว่างกล้องหน้าและกล้องหลังได้สะดวก
และหากอุปกรณ์ไม่มีกล้อง หรือผู้ใช้ปฏิเสธสิทธิ์การเข้าถึงกล้อง ระบบจะต้องมีข้อความแจ้งเตือนที่ชัดเจนและให้ทางเลือกในการเลือกไฟล์ภาพจากเครื่องแทนได้

**Why this priority**:
ช่วยรองรับความหลากหลายของฮาร์ดแวร์หน้าร้าน (เช่น แท็บเล็ต Android/iPad, เครื่อง POS All-in-one ที่มีเว็บแคม, โน้ตบุ๊ก) ช่วยให้การทำงานไม่ติดขัดหากเกิดข้อจำกัดด้านฮาร์ดแวร์หรือสิทธิ์การใช้งาน

**Independent Test**:
ทดสอบบนอุปกรณ์ที่มีกล้องหน้าและกล้องหลัง สามารถกดปุ่มสลับกล้องและเห็นภาพเปลี่ยนมุมมองได้ และทดสอบในกรณีปฏิเสธสิทธิ์กล้อง ระบบจะแสดงคำแนะนำที่เข้าใจง่ายและยังคงสามารถกดเลือกไฟล์ภาพตามปกติได้

**Acceptance Scenarios**:

1. **สลับกล้องหน้า/กล้องหลัง**: **Given** อุปกรณ์มีกล้องมากกว่า 1 ตัวและเปิดหน้าต่างถ่ายภาพอยู่, **When** ผู้ใช้กดปุ่ม "สลับกล้อง", **Then** ระบบจะสลับสัญญาณภาพไปยังอีกกล้องหนึ่งอย่างราบรื่น
2. **จัดการกรณีไม่อนุญาตให้ใช้กล้อง**: **Given** ผู้ใช้กดปฏิเสธสิทธิ์การเข้าถึงกล้องในเบราว์เซอร์, **When** ผู้ใช้พยายามกดปุ่ม "ถ่ายภาพด้วยกล้อง", **Then** ระบบแสดงข้อความแจ้งเตือนที่ชัดเจนว่า "ไม่สามารถเข้าถึงกล้องได้ กรุณาอนุญาตสิทธิ์การใช้งานกล้องในเบราว์เซอร์ หรือใช้วิธีเลือกไฟล์รูปภาพแทน"
3. **คงปุ่มเลือกไฟล์ภาพปกติไว้**: **Given** ผู้ใช้อยู่ในส่วนรูปภาพของแบบฟอร์มแก้ไขสินค้า, **When** ผู้ใช้ดูตัวเลือกการแนบภาพ, **Then** มีทั้งปุ่ม "ถ่ายภาพ" และปุ่ม "เลือกไฟล์" ให้เลือกใช้งานได้อย่างอิสระ

---

### Edge Cases

- **กรณีอุปกรณ์ไม่มีกล้อง**: ระบบต้องตรวจจับว่าอุปกรณ์มีอุปกรณ์รับสัญญาณภาพหรือไม่ หากไม่มี ให้ปิดการใช้งานปุ่มถ่ายภาพหรือแสดงข้อความแจ้งเมื่อกด โดยไม่เกิดข้อผิดพลาดของระบบ (No App Crash)
- **กรณีการเชื่อมต่ออินเทอร์เน็ตหลุดระหว่างอัปโหลดภาพ**: ระบบต้องแจ้งเตือนข้อผิดพลาดในการอัปโหลดภาพอย่างชัดเจน และให้ทางเลือกในการลองใหม่อีกครั้ง
- **กรณีรูปภาพที่ถ่ายมีขนาดใหญ่มาก**: ระบบต้องปรับขนาดและบีบอัดรูปภาพให้อยู่ในขนาดที่เหมาะสมสำหรับการแสดงผลบนระบบ POS ก่อนส่งบันทึก เพื่อความรวดเร็วในการส่งข้อมูลและประหยัดพื้นที่จัดเก็บ
- **กรณีปิดหน้าต่างถ่ายภาพกะทันหัน**: หากผู้ใช้กดยกเลิกหรือปิดหน้าต่างถ่ายภาพ ระบบต้องปิดการทำงานของกล้อง (Release Camera Stream) ทันทีเพื่อไม่ให้กล้องทำงานค้างและประหยัดพลังงานแบตเตอรี่
- **กรณีไม่มีการแก้ไขรูปภาพ แต่แก้ไขข้อมูลอื่น (เช่น ราคา, ชื่อสินค้า)**: เมื่อบันทึกสำเร็จ ภาพเดิมในหน้ารายการต้องยังคงแสดงผลถูกต้อง ไม่สูญหายหรือกลายเป็นภาพว่าง

---

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ระบบต้องมีปุ่มสำหรับ "ถ่ายภาพด้วยกล้อง" ควบคู่ไปกับปุ่ม "เลือกไฟล์ภาพ" ในส่วนจัดการรูปภาพสินค้าของแบบฟอร์มแก้ไขข้อมูลสินค้า
- **FR-002**: ระบบต้องรองรับการเปิดใช้งานกล้องของอุปกรณ์ผ่านเว็บเบราว์เซอร์ เพื่อแสดงภาพตัวอย่างสด (Live Viewfinder) แบบเต็มตาและชัดเจน
- **FR-003**: ระบบต้องมีปุ่มชัตเตอร์ขนาดใหญ่ (Touch target อย่างน้อย 48x48px ตามมาตรฐานผู้ใช้งานทุกกลุ่ม) สำหรับกดจับภาพนิ่งจากกล้อง
- **FR-004**: เมื่อกดถ่ายภาพแล้ว ระบบต้องแสดงภาพที่ถ่ายเพื่อให้ผู้ใช้ตรวจสอบคุณภาพ พร้อมปุ่ม "ถ่ายใหม่" (Retake) และปุ่ม "ใช้ภาพนี้" (Accept)
- **FR-005**: ระบบต้องปิดการใช้งานกล้อง (Stop Camera Stream/Tracks) ทันทีเมื่อผู้ใช้ปิดหน้าต่างกล้อง หรือกดยืนยันการใช้ภาพ
- **FR-006**: ระบบต้องรองรับการสลับกล้อง (หน้า/หลัง หรือกล้องตัวอื่นที่เชื่อมต่ออยู่) หากอุปกรณ์มีกล้องมากกว่าหนึ่งตัว
- **FR-007**: ระบบต้องแสดงข้อความแจ้งเตือนเป็นภาษาไทยที่สุภาพและเข้าใจง่าย หากไม่สามารถเข้าถึงกล้องได้เนื่องจากไม่มีสิทธิ์หรือไม่มีอุปกรณ์
- **FR-008**: เมื่อผู้ใช้กดยืนยันบันทึกการแก้ไขข้อมูลสินค้าที่มีการถ่ายภาพใหม่ ระบบต้องส่งข้อมูลแก้ไขพร้อมอัปโหลดรูปภาพใหม่ให้เสร็จสมบูรณ์
- **FR-009**: หลังจากบันทึกข้อมูลและอัปโหลดภาพสินค้าสำเร็จ ระบบต้องอัปเดตข้อมูลและรูปภาพในตารางรายการสินค้า (Product Catalog List) ทันทีในหน่วยความจำหน้าจอ โดยผู้ใช้ไม่ต้องกดรีเฟรชหน้าเว็บ (No Page Reload)
- **FR-010**: รูปภาพใหม่ที่แสดงในตารางรายการสินค้าต้องเป็นภาพล่าสุด โดยมีการจัดการไม่ให้เบราว์เซอร์นำภาพเก่าจากแคชมาแสดงซ้ำ (Cache Busting)
- **FR-011**: หากการอัปโหลดรูปภาพล้มเหลว ระบบต้องแจ้งเตือนให้ผู้ใช้ทราบอย่างชัดเจน พร้อมบอกสถานะว่าข้อมูลข้อความบันทึกสำเร็จหรือไม่ เพื่อให้ผู้ใช้ตัดสินใจอัปโหลดรูปภาพใหม่อีกครั้ง
- **FR-012**: องค์ประกอบปุ่มกดทั้งหมดที่เกี่ยวข้องกับการควบคุมกล้อง ถ่ายภาพ และยืนยัน ต้องมีขนาดไม่เล็กกว่า 48x48px และมีคอนทราสต์ที่ชัดเจนตามมาตรฐาน Elderly-Friendly ของธรรมนูญระบบ

### Key Entities *(include if feature involves data)*

- **Product (ข้อมูลสินค้า)**: ข้อมูลสินค้าที่ถูกแก้ไข ประกอบด้วย รหัสประจำตัวสินค้า (ID), รหัสสินค้า (SKU), ชื่อสินค้า (Name), หมวดหมู่ (Category), ราคา (Price), สถานะเปิด/ปิดจำหน่าย (Active Status) และที่อยู่รูปภาพ (Image URL / Timestamp)
- **Captured Image (ภาพถ่ายจากกล้อง)**: ข้อมูลภาพถ่ายสดจากกล้องที่ถูกแปลงเป็นไฟล์รูปภาพ (Image Blob/File) มีข้อมูลชนิดไฟล์ (MIME Type: image/jpeg หรือ image/webp), ขนาดไฟล์ (File Size), และที่อยู่ภาพจำลองสำหรับการแสดงผลตัวอย่าง (Preview Object URL)
- **Media Stream / Camera Device (อุปกรณ์กล้อง)**: อุปกรณ์รับภาพของระบบ ประกอบด้วย รหัสกล้อง (Device ID), ตำแหน่งกล้อง (Facing Mode: environment สำหรับกล้องหลัง, user สำหรับกล้องหน้า), และสถานะการอนุญาตใช้งาน (Permission Status)

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ผู้ใช้สามารถเปิดกล้อง ถ่ายภาพสินค้า และกดยืนยันนำภาพมาใส่ในฟอร์มแก้ไขสินค้าได้สำเร็จภายในเวลาไม่เกิน 15 วินาที
- **SC-002**: หลังจากกดปุ่มบันทึกข้อมูลสินค้า รูปภาพใหม่ต้องปรากฏในตารางรายการสินค้าหน้าร้านทันทีภายในเวลาไม่เกิน 1 วินาที โดยไม่ต้องกดรีเฟรชหน้าเบราว์เซอร์
- **SC-003**: อัตราความสำเร็จในการจับภาพและแสดงผลถูกต้อง (First-time Capture & Display Accuracy) ไม่น้อยกว่า 98% บนอุปกรณ์ที่รองรับกล้อง
- **SC-004**: เมื่อผู้ใช้ปฏิเสธสิทธิ์กล้องหรือไม่มีกล้อง ระบบสามารถแสดงทางเลือกสำรอง (เช่น อัปโหลดไฟล์) ให้ผู้ใช้ดำเนินงานต่อได้ 100% โดยไม่มีข้อผิดพลาดที่ทำให้หน้าจอค้าง
- **SC-005**: องค์ประกอบปุ่มกดถ่ายภาพและจัดการรูปภาพทั้งหมดมีขนาด Touch Target ผ่านเกณฑ์มาตรฐานขั้นต่ำ 48x48px ครบ 100%

## Assumptions

- อุปกรณ์ที่ใช้งาน (แท็บเล็ต POS, สมาร์ตโฟน หรือคอมพิวเตอร์) ใช้งานผ่านเบราว์เซอร์สมัยใหม่ที่รองรับมาตรฐานการเข้าถึงกล้อง (เช่น HTML5 MediaDevices / getUserMedia หรือ Camera File Capture) และทำงานบนโปรโตคอลที่ปลอดภัย (HTTPS หรือ Localhost) ตามข้อกำหนดความปลอดภัยของเบราว์เซอร์
- การถ่ายภาพจากกล้องจะเสริมเข้ากับระบบเดิม โดยยังคงความสามารถในการลากวางหรือเลือกไฟล์ภาพจากเครื่องไว้เช่นเดิม ไม่ได้ตัดฟังก์ชันเดิมออก
- รูปภาพที่ถ่ายจะถูกจัดเตรียมในรูปแบบมาตรฐาน (JPEG/WebP) ที่มีความละเอียดและขนาดไฟล์เหมาะสม เพื่อให้การอัปโหลดผ่านเครือข่ายร้านค้าเป็นไปอย่างรวดเร็ว
- ระบบจัดการแคชของรูปภาพในตารางรายการสินค้าจะใช้การระบุพารามิเตอร์เวลาหรืออัปเดต URL เพื่อให้เบราว์เซอร์ดึงภาพใหม่ล่าสุดมาแสดงทันที
