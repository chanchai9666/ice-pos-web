# Feature Specification: การปรับปรุงระบบพิสูจน์ตัวตนแบบผสมผสาน (Hybrid Authentication Support)

**Feature Branch**: `009-hybrid-auth-support`

**Created**: 2026-10-25

**Status**: Draft

**Input**: User description: "ปรับปรุงรองรับแบบ Hybrid Support"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - การเข้าถึงระบบและส่งคำขอด้วยระบบรับรองสิทธิ์แบบผสมผสาน (Dual-Credential API Access) (Priority: P1)

แคชเชียร์และผู้ใช้งานระบบ POS สามารถลงชื่อเข้าใช้งานและทำรายการต่างๆ ผ่านระบบได้อย่างราบรื่นและมีความปลอดภัยสูง โดยระบบรองรับการยืนยันตัวตนแบบผสมผสาน (Hybrid Support) ทั้งผ่านคุกกี้นิรภัยที่เบราว์เซอร์เป็นผู้ดูแล (Secure HttpOnly Cookie) เพื่อป้องกันการโจมตีทางไซเบอร์ และผ่านการแนบข้อมูลสิทธิ์ในส่วนหัวคำขอ (Authorization Header) ในกรณีจำเป็น ทำให้ระบบสามารถทำงานร่วมกับบริการหลังบ้านได้อย่างสมบูรณ์ในทุกสภาวะแวดล้อมโดยไม่ถูกปฏิเสธสิทธิ์

**Why this priority**: การรักษาความปลอดภัยของข้อมูลการขายและสิทธิ์ของพนักงานเป็นหัวใจสำคัญของระบบ POS ขณะเดียวกันการทำให้ระบบสามารถรับส่งคำขอได้อย่างราบรื่นโดยไม่หลุดออกจากระบบเป็นสิ่งจำเป็นต่อการขายหน้าร้าน

**Independent Test**: เข้าสู่ระบบ POS จากนั้นทำรายการเรียกดูข้อมูลสินค้า ข้อมูลยอดขาย และทำรายการขาย ตรวจสอบว่าระบบสามารถสื่อสารกับบริการเบื้องหลังได้สำเร็จอย่างต่อเนื่อง โดยมีการส่งข้อมูลยืนยันตัวตนที่ปลอดภัยและไม่มีข้อผิดพลาดด้านการยืนยันสิทธิ์

**Acceptance Scenarios**:

1. **Given** แคชเชียร์เข้าสู่ระบบสำเร็จ, **When** ระบบส่งคำขอเรียกดูหรือบันทึกข้อมูลไปยังระบบหลังบ้าน, **Then** ระบบจะส่งคำขอพร้อมการเปิดสิทธิ์ส่งข้อมูลรับรอง (Credentials Included) เพื่อให้เบราว์เซอร์แนบคุกกี้นิรภัยไปกับคำขอโดยอัตโนมัติ
2. **Given** มีข้อมูลสิทธิ์การเข้าถึงอยู่ในระบบ, **When** ระบบส่งคำขอไปยังระบบหลังบ้าน, **Then** ระบบสามารถแนบข้อมูลสิทธิ์ในส่วนหัวของคำขอควบคู่ไปด้วย เพื่อให้บริการที่ต้องการการตรวจสอบสิทธิ์แบบผสมผสานสามารถประมวลผลคำขอได้สำเร็จ 100%
3. **Given** แคชเชียร์กำลังใช้งานหน้าจอ POS เช่น ยิงบาร์โค้ด ค้นหาสินค้า หรือรับชำระเงิน, **When** มีการส่งคำขอเกิดขึ้น, **Then** การทำงานบนหน้าจอต้องตอบสนองทันที ไม่มีการหน่วงหรือแสดงข้อผิดพลาดเกี่ยวกับสิทธิ์การใช้งาน

### User Story 2 - การต่ออายุเซสชันการใช้งานอย่างต่อเนื่องผ่านช่องทางผสมผสาน (Silent Session Renewal via Hybrid Channels) (Priority: P1)

เมื่อสิทธิ์การเข้าถึงเดิมใกล้หมดอายุหรือหมดอายุขณะที่แคชเชียร์กำลังปฏิบัติงานขายอย่างต่อเนื่อง ระบบจะทำการต่ออายุเซสชันเบื้องหลังโดยอัตโนมัติ (Silent Refresh) ผ่านช่องทางแบบผสมผสาน โดยสามารถขอต่ออายุสิทธิ์ผ่านคุกกี้ที่เก็บไว้อย่างปลอดภัย หรือส่งข้อมูลต่ออายุควบคู่ไป เพื่อให้เซิร์ฟเวอร์สามารถออกสิทธิ์การเข้าถึงชุดใหม่ได้อย่างต่อเนื่อง ทำให้แคชเชียร์ขายสินค้าได้ตลอดทั้งกะโดยไม่พบหน้าต่างเด้งหลุดออกจากระบบ

**Why this priority**: การป้องกันไม่ให้แคชเชียร์หลุดออกจากระบบขณะกำลังคิดเงินให้ลูกค้าหน้าร้านมีความสำคัญสูงสุดต่อประสบการณ์ของลูกค้าและประสิทธิภาพของร้านค้า

**Independent Test**: จำลองสภาวะที่สิทธิ์การเข้าถึงเดิมหมดอายุระหว่างการใช้งานหน้าจอ POS ตรวจสอบว่าระบบต่ออายุเซสชันเบื้องหลังสำเร็จ ส่งคำขอเดิมซ้ำให้อัตโนมัติ และแคชเชียร์สามารถกดชำระเงินต่อได้ทันทีโดยไม่มีการแจ้งเตือนขัดจังหวะ

**Acceptance Scenarios**:

1. **Given** แคชเชียร์กำลังปฏิบัติงานบนหน้าจอขาย และสิทธิ์การเข้าถึงเดิมหมดอายุ, **When** มีการส่งคำขอไปยังระบบหลังบ้าน, **Then** ระบบดำเนินการขอต่ออายุสิทธิ์ใหม่ในเบื้องหลังโดยอัตโนมัติผ่านช่องทางรับรองที่เปิดใช้งาน และส่งคำขอเดิมซ้ำให้อย่างราบรื่น
2. **Given** มีการส่งคำขอหลายรายการพร้อมกันขณะที่สิทธิ์การเข้าถึงหมดอายุ, **When** ระบบตรวจพบสถานะดังกล่าว, **Then** ระบบจะรวบรวมคำขอต่ออายุให้เกิดขึ้นเพียงครั้งเดียว (Single-flight Refresh) เพื่อป้องกันการส่งคำขอต่ออายุซ้ำซ้อน
3. **Given** เซิร์ฟเวอร์ส่งข้อมูลสิทธิ์ชุดใหม่กลับมา (ทั้งในรูปแบบคุกกี้ใหม่และข้อมูลสิทธิ์ในผลลัพธ์), **When** การต่ออายุสำเร็จ, **Then** ระบบบันทึกและปรับปรุงสถานะเซสชันให้พร้อมใช้งานอย่างต่อเนื่องในทันที

### User Story 3 - การออกจากระบบอย่างสมบูรณ์ทั้งฝั่งเซิร์ฟเวอร์และอุปกรณ์ (Comprehensive Dual-Clear Logout) (Priority: P2)

เมื่อผู้ใช้งานต้องการออกจากระบบด้วยตนเอง (Manual Logout) หรือเมื่อเซสชันหมดอายุถาวรจนไม่สามารถต่ออายุได้ ระบบจะส่งคำขอแจ้งยกเลิกเซสชันไปยังเซิร์ฟเวอร์เพื่อสั่งล้างคุกกี้นิรภัยออกจากเบราว์เซอร์ พร้อมทั้งล้างข้อมูลโปรไฟล์และสถานะการเข้าใช้งานออกจากอุปกรณ์อย่างหมดจด เพื่อความปลอดภัยสูงสุด ป้องกันการเข้าถึงข้อมูลโดยไม่ได้รับอนุญาต โดยระบบยังคงจดจำข้อมูลสาขาเพื่ออำนวยความสะดวกให้แคชเชียร์คนถัดไปสามารถเข้าสู่ระบบด้วยรหัส PIN ได้อย่างรวดเร็ว

**Why this priority**: การล้างเซสชันอย่างสมบูรณ์ทั้งสองฝั่ง (เซิร์ฟเวอร์และอุปกรณ์) เป็นมาตรฐานความปลอดภัยที่จำเป็นเมื่อใช้งานระบบคุกกี้นิรภัย เพื่อให้มั่นใจว่าไม่มีสิทธิ์ตกค้างในเบราว์เซอร์หลังออกจากระบบ

**Independent Test**: กดปุ่มออกจากระบบจากเมนูผู้ใช้ ตรวจสอบว่าระบบส่งคำขอแจ้งเซิร์ฟเวอร์เพื่อล้างคุกกี้ และล้างข้อมูลเซสชันในเครื่องออกทั้งหมด จากนั้นนำทางกลับสู่หน้าล็อกอินโดยยังคงจำสาขาเดิมไว้

**Acceptance Scenarios**:

1. **Given** ผู้ใช้งานกดปุ่ม "ออกจากระบบ" บนหน้าจอ, **When** ระบบเริ่มกระบวนการออกจากระบบ, **Then** ระบบจะส่งคำขอไปยังจุดให้บริการแจ้งออกจากระบบของเซิร์ฟเวอร์ เพื่อให้เซิร์ฟเวอร์สั่งลบและยกเลิกคุกกี้นิรภัยในเบราว์เซอร์
2. **Given** คำขอออกจากระบบถูกส่งออกไป (ไม่ว่าผลลัพธ์จากเครือข่ายจะสำเร็จหรือล้มเหลว), **When** กระบวนการสิ้นสุด, **Then** ระบบต้องล้างข้อมูลสิทธิ์และโปรไฟล์ผู้ใช้งานออกจากหน่วยความจำของอุปกรณ์อย่างแน่นอน 100%
3. **Given** การออกจากระบบเสร็จสิ้น, **When** หน้าจอนำทางกลับมายังหน้าเข้าสู่ระบบ, **Then** ข้อมูลสาขาล่าสุดยังคงถูกเลือกไว้ เพื่อให้สามารถกดปุ่มรหัส PIN เข้าทำงานต่อได้ทันที

### User Story 4 - การรักษาข้อมูลงานขายและความเข้ากันได้ (POS Continuity & Graceful Fallback) (Priority: P2)

ในกรณีที่เซสชันหมดอายุระหว่างการขาย หรืออุปกรณ์มีการสลับโหมดการเชื่อมต่อ ระบบจะต้องคงรายการสินค้าในตะกร้าขาย (Cart Items) ไว้ ไม่ลบทิ้ง เพื่อให้แคชเชียร์สามารถป้อนรหัส PIN กลับเข้ามาและขายสินค้าต่อได้ทันที และหากเซิร์ฟเวอร์ยังตอบสนองด้วยกลไกการยืนยันตัวตนแบบเดิม ระบบหน้าบ้านจะต้องรองรับได้อย่างกลมกลืนโดยไม่หยุดการทำงาน

**Why this priority**: การไม่สูญเสียรายการสินค้าที่ยิงบาร์โค้ดไว้ช่วยลดความหงุดหงิดของลูกค้าที่ยืนรอหน้าร้าน และช่วยให้แคชเชียร์ปฏิบัติงานได้อย่างมั่นใจ

**Independent Test**: เพิ่มสินค้าลงในตะกร้าขาย แล้วจำลองการหมดอายุของเซสชันจนระบบนำทางไปหน้าล็อกอิน จากนั้นเข้าสู่ระบบด้วยรหัส PIN ตรวจสอบว่ารายการสินค้าในตะกร้ายังคงอยู่ครบถ้วน

**Acceptance Scenarios**:

1. **Given** มีรายการสินค้าค้างอยู่ในตะกร้าขาย และเซสชันหมดอายุจนต้องเข้าสู่ระบบใหม่, **When** แคชเชียร์ใส่รหัส PIN กลับเข้ามาในระบบ, **Then** รายการสินค้าในตะกร้าขายยังคงอยู่ครบถ้วนพร้อมทำการขายต่อได้ทันที
2. **Given** ระบบทำงานในสภาพแวดล้อมที่รองรับเฉพาะคุกกี้ หรือรองรับเฉพาะส่วนหัวคำขอ, **When** ผู้ใช้ทำรายการ, **Then** ระบบยังคงสามารถทำงานได้ตามปกติโดยไม่มีข้อผิดพลาดเกี่ยวกับความไม่เข้ากันของข้อมูลสิทธิ์

---

### Edge Cases

- **กรณีเครือข่ายขัดข้องขณะส่งคำขอออกจากระบบ (Network Failure during Logout)**: หากเครือข่ายหลุดขณะกดออกจากระบบ ระบบต้องไม่บล็อกหน้าจอค้างไว้ แต่ต้องดำเนินการล้างข้อมูลเซสชันในเครื่องและนำทางกลับไปยังหน้าล็อกอินทันที เพื่อความปลอดภัยของข้อมูลบนอุปกรณ์
- **กรณีเซิร์ฟเวอร์ส่งสัญญาณปฏิเสธสิทธิ์ (401 Unauthorized) อย่างถาวร**: เมื่อไม่สามารถต่ออายุสิทธิ์ได้ ระบบต้องไม่วนซ้ำส่งคำขอต่ออายุไม่รู้จบ แต่ต้องตัดเข้าสู่กระบวนการแจ้งเตือนเซสชันหมดอายุและนำทางไปหน้าล็อกอินอย่างปลอดภัย
- **กรณีการใช้งานข้ามโดเมนหรือการตั้งค่าคุ้มครองความเป็นส่วนตัวของเบราว์เซอร์ (Strict Privacy / Third-Party Cookie Settings)**: ระบบต้องคงความเข้ากันได้แบบผสมผสาน (Hybrid) เพื่อให้คำขอยังคงได้รับการตรวจสอบสิทธิ์อย่างถูกต้อง
- **กรณีการรีเฟรชหน้าจอ (Page Reload) ขณะใช้งาน**: ระบบต้องสามารถกู้คืนสถานะการเข้าสู่ระบบและข้อมูลผู้ใช้งานได้อย่างถูกต้องโดยไม่ต้องบังคับให้ผู้ใช้ล็อกอินซ้ำ

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: ระบบส่งคำขอ (API Client / Request Dispatcher) ต้องเปิดใช้งานการส่งผ่านข้อมูลรับรองสิทธิ์ (Include Credentials) ในทุกคำขอไปยังเซิร์ฟเวอร์ เพื่อให้เบราว์เซอร์สามารถส่งและรับคุกกี้นิรภัย (HttpOnly Cookie) ได้อย่างอัตโนมัติ
- **FR-002**: ระบบต้องรองรับการยืนยันตัวตนแบบผสมผสาน (Hybrid Authentication) โดยสามารถส่งข้อมูลสิทธิ์ผ่านทั้งคุกกี้ที่ปลอดภัยและส่วนหัวของคำขอ เพื่อความเข้ากันได้สูงสุดกับบริการทั้งหมด
- **FR-003**: เมื่อทำการต่ออายุเซสชัน (Token Refresh) ระบบต้องส่งคำขอต่ออายุที่รองรับช่องทางแบบผสมผสาน (สามารถต่ออายุผ่านคุกกี้ หรือผ่านข้อมูลการต่ออายุที่แนบไป) พร้อมทั้งปรับปรุงสิทธิ์ใหม่เข้าสู่ระบบอย่างสมบูรณ์
- **FR-004**: ระบบต้องมีกลไกบริหารจัดการคิวการต่ออายุสิทธิ์ (Refresh Coordinator) เพื่อให้คำขอต่ออายุเกิดขึ้นเพียงครั้งเดียวเมื่อมีคำขอหลายรายการตรวจพบว่าสิทธิ์หมดอายุพร้อมกัน (Single-Flight Pattern)
- **FR-005**: ระบบต้องมีกระบวนการแจ้งออกจากระบบไปยังเซิร์ฟเวอร์ (Server Logout Notification) เพื่อให้เซิร์ฟเวอร์ทำการยกเลิกและสั่งล้างคุกกี้นิรภัยออกจากเบราว์เซอร์อย่างเป็นทางการ
- **FR-006**: เมื่อเกิดการออกจากระบบ (ไม่ว่าจะด้วยคำสั่งของผู้ใช้ หรือเนื่องจากเซสชันหมดอายุ) ระบบต้องล้างข้อมูลสิทธิ์และข้อมูลโปรไฟล์ผู้ใช้ออกจากหน่วยจัดเก็บของอุปกรณ์อย่างสมบูรณ์
- **FR-007**: ระบบต้องคงข้อมูลสาขาที่เลือกใช้งานล่าสุดไว้ แม้จะมีการออกจากระบบ เพื่อให้ผู้ใช้งานสามารถเข้าสู่ระบบด่วนด้วยรหัส PIN ได้ทันทีโดยไม่ต้องเลือกสาขาซ้ำ
- **FR-008**: ระบบต้องคงรายการสินค้าในตะกร้าขาย (Cart Items) ไว้เมื่อเกิดกรณีเซสชันหมดอายุ เพื่อให้แคชเชียร์กลับเข้ามาทำรายการต่อได้อย่างรวดเร็ว
- **FR-009**: เมื่อเซสชันหมดอายุและไม่สามารถต่ออายุได้ ระบบต้องแสดงข้อความแจ้งเตือนภาษาไทยที่กระชับและเข้าใจง่าย เช่น "เซสชันการใช้งานหมดอายุ กรุณาเข้าสู่ระบบใหม่อีกครั้ง"
- **FR-010**: ข้อความแจ้งเตือน ปุ่มกด และองค์ประกอบที่เกี่ยวข้องกับความปลอดภัยและเซสชัน ต้องปฏิบัติตามมาตรฐาน Elderly-Friendly (ขนาดตัวอักษรไม่เล็กกว่า 16px, พื้นที่สัมผัสอย่างน้อย 48x48px และมีคอนทราสต์ชัดเจนตามมาตรฐาน WCAG 2.1 AA)

### Key Entities *(include if feature involves data)*

- **Session Context**: บริบทสถานะการเข้าสู่ระบบของผู้ใช้งาน ประกอบด้วยข้อมูลผู้ใช้ปัจจุบัน (User Profile), ข้อมูลสิทธิ์การเข้าถึง (Credentials), สถานะความพร้อมของเซสชัน, และสาขาปัจจุบันที่กำลังปฏิบัติงาน
- **Hybrid Request Configuration**: การตั้งค่าการส่งคำขอระดับระบบที่ควบคุมการแนบข้อมูลรับรองความปลอดภัย (Credentials Include Flag) และการระบุส่วนหัวของคำขอ
- **Session Lifecycle Event**: เหตุการณ์การเปลี่ยนแปลงวงจรชีวิตของเซสชัน ได้แก่ การเข้าสู่ระบบสำเร็จ (LOGIN_SUCCESS), การเริ่มต่ออายุสิทธิ์เบื้องหลัง (REFRESHING), การต่ออายุสำเร็จ (REFRESH_SUCCESS), การหมดอายุถาวร (SESSION_EXPIRED), และการออกจากระบบ (LOGOUT)
- **Continuity State**: ข้อมูลคงค้างที่ต้องรักษาไว้ข้ามเซสชัน ได้แก่ สาขาล่าสุด และรายการสินค้าในตะกร้าขาย

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% ของคำขอไปยังระบบหลังบ้านได้รับการเปิดใช้งานการส่งผ่านข้อมูลรับรองสิทธิ์ (Credentials Included) อย่างถูกต้องและสม่ำเสมอ
- **SC-002**: การต่ออายุสิทธิ์เบื้องหลังขณะแคชเชียร์กำลังใช้งานต่อเนื่อง สามารถทำงานได้อย่างเงียบสนิท (Silent Refresh) โดยผู้ใช้งาน 0% พบการสะดุดหรือหน้าจอกะพริบระหว่างการปฏิบัติงาน
- **SC-003**: 100% ของการกดออกจากระบบ สามารถส่งคำขอแจ้งยกเลิกเซสชันไปยังเซิร์ฟเวอร์เพื่อล้างคุกกี้นิรภัย และล้างข้อมูลสิทธิ์ในอุปกรณ์ได้อย่างครบถ้วน
- **SC-004**: แคชเชียร์สามารถป้อนรหัส PIN เพื่อกลับเข้าสู่ระบบและเริ่มทำงานต่อได้ภายในเวลาไม่เกิน 5 วินาทีหลังจากเกิดกรณีเซสชันหมดอายุ
- **SC-005**: 100% ของกรณีเซสชันหมดอายุ มีการแสดงข้อความแจ้งเตือนภาษาไทยที่ชัดเจนให้อ่านได้ทันทีภายใน 1 วินาทีหลังการนำทางหน้าจอ

## Assumptions

- ระบบบริการหลังบ้าน (`ice-pos-api`) รองรับการตรวจสอบสิทธิ์แบบผสมผสาน (Hybrid Authentication) โดยสามารถอ่านสิทธิ์ได้ทั้งจากคุกกี้นิรภัยและส่วนหัวคำขอ รวมถึงมีจุดให้บริการสำหรับการยกเลิกเซสชัน (`/api/v1/auth/logout`)
- เบราว์เซอร์ที่ใช้ปฏิบัติงานหน้าร้าน POS เป็นเบราว์เซอร์มาตรฐานสมัยใหม่ที่รองรับการจัดการคุกกี้และการรับส่งข้อมูลรับรองผ่านเครือข่ายตามมาตรฐานความปลอดภัย
- การจัดเก็บข้อมูลสาขาและรายการสินค้าในตะกร้าขายยังคงใช้กลไกการจัดเก็บบนอุปกรณ์ตามมาตรฐานเดิม เพื่ออำนวยความสะดวกในการปฏิบัติงานต่อเนื่องของแคชเชียร์
- เพื่อความปลอดภัยสูงสุด ระบบจะมุ่งเน้นการใช้คุกกี้นิรภัยเป็นช่องทางหลัก และส่งข้อมูลผ่านส่วนหัวควบคู่เพื่อความเข้ากันได้แบบผสมผสาน
