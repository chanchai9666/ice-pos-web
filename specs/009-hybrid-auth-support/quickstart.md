# Quickstart & Validation Guide: Hybrid Authentication Support

**Branch**: `009-hybrid-auth-support`  
**Feature**: `specs/009-hybrid-auth-support/spec.md`  

คู่มือนี้ระบุขั้นตอนการทดสอบและตรวจสอบการทำงานของระบบยืนยันตัวตนแบบผสมผสาน (Hybrid Authentication)

---

## 1. ข้อกำหนดเบื้องต้น (Prerequisites)

- รัน `ice-pos-api` (เซิร์ฟเวอร์หลังบ้าน) ที่รองรับ Hybrid Auth (`http://127.0.0.1:8080`)
- รัน `ice-pos-web` (หน้าบ้าน Next.js): `npm run dev` (`http://localhost:3000`)
- มีข้อมูลบัญชีผู้ใช้ทดสอบ เช่น แคชเชียร์ที่มีรหัส PIN และชื่อผู้ใช้งาน/รหัสผ่าน

---

## 2. สถานการณ์ทดสอบที่ 1: การเข้าสู่ระบบและการส่งผ่านข้อมูลรับรอง (Login & Credentials Transmission)

### ขั้นตอน:
1. เปิดเบราว์เซอร์ไปที่ `http://localhost:3000/login`
2. เข้าสู่ระบบด้วยรหัส PIN หรือ Username/Password
3. เปิด DevTools > Application/Storage > Cookies (`http://127.0.0.1:8080` หรือ `http://localhost:3000`)
4. สังเกตคุกกี้ `access_token` และ `refresh_token` ที่ถูกบันทึกพร้อมสถานะ `HttpOnly`
5. เปิดแท็บ Network ใน DevTools แล้วกดดูสินค้าหรือทำรายการในหน้า `/pos`
6. ตรวจสอบคำขอที่ส่งออกไป:
   - ตรวจสอบว่าคำขอมี Request Headers ส่ง `Cookie: access_token=...` และ/หรือ `Authorization: Bearer ...`
   - ตรวจสอบว่าผลลัพธ์ตอบกลับด้วย `200 OK`

---

## 3. สถานการณ์ทดสอบที่ 2: การต่ออายุเซสชันเบื้องหลังแบบผสมผสาน (Silent Token Refresh)

### ขั้นตอน:
1. เข้าสู่ระบบและเปิดหน้าจอขายหน้าร้าน `/pos`
2. จำลองให้ `access_token` หมดอายุ (หรือรอจนครบกำหนดอายุ 15 นาที)
3. ยิงบาร์โค้ดหรือกดเลือกสินค้าบนหน้าจอ POS
4. สังเกตแท็บ Network:
   - คำขอแรกจะได้รับ `401 Unauthorized`
   - ระบบจะส่งคำขอ `POST /api/v1/auth/refresh` เบื้องหลังทันทีโดยมี `credentials: 'include'`
   - เมื่อ Refresh สำเร็จ คำขอเดิมจะถูก Retry อัตโนมัติและสำเร็จด้วย `200 OK`
   - หน้าจอไม่มีการกระตุก ไม่มีการรีโหลดหน้าเว็บ และแคชเชียร์ขายสินค้าต่อได้ทันที

---

## 4. สถานการณ์ทดสอบที่ 3: การออกจากระบบอย่างสมบูรณ์ (Complete Dual Logout)

### ขั้นตอน:
1. เข้าสู่ระบบและเลือกสาขา เช่น "สาขาหลัก สำนักงานใหญ่"
2. กดที่ปุ่มโปรไฟล์ผู้ใช้ และเลือก "ออกจากระบบ"
3. สังเกตแท็บ Network:
   - มีคำขอ `POST /api/v1/auth/logout` ส่งไปยังเซิร์ฟเวอร์
   - เซิร์ฟเวอร์ส่ง `Set-Cookie` ล้างคุกกี้ (`MaxAge=-1`)
4. สังเกต DevTools > Application:
   - คุกกี้ `access_token` และ `refresh_token` หายไป
   - `localStorage` ไม่มี `ice_pos_access_token` หรือ `ice_pos_user_profile`
   - ข้อมูลสาขา `ice_pos_current_branch` และ `ice_pos_last_branch_id` ยังคงอยู่
5. หน้าจอเปลี่ยนไปยัง `/login` พร้อมแสดงสาขาเดิมที่เลือกไว้

---

## 5. สถานการณ์ทดสอบที่ 4: ความต่อเนื่องของงานขายเมื่อเซสชันหมดอายุ (Cart Continuity)

### ขั้นตอน:
1. เพิ่มสินค้าลงในตะกร้า 3 รายการ
2. จำลองเซสชันหมดอายุถาวร (ทั้ง Access Token และ Refresh Token)
3. ระบบนำทางไปยังหน้า `/login?expired=1` พร้อมแสดงข้อความเตือนภาษาไทย "เซสชันการใช้งานหมดอายุ กรุณาเข้าสู่ระบบใหม่อีกครั้ง"
4. แคชเชียร์กดป้อนรหัส PIN เดิมเพื่อเข้าสู่ระบบ
5. ระบบนำทางกลับไปยังหน้า `/pos` และรายการสินค้าทั้ง 3 รายการในตะกร้ายังคงอยู่ครบถ้วน
