# Quickstart Validation: Catalog Product Form Barcode Scan

**Feature**: `015-catalog-barcode-scan`  
**Date**: 2026-10-27

## Prerequisites

- Dev server รันได้: `npm run dev`
- เข้าสู่ระบบและเปิดหน้า [http://localhost:3000/catalog](http://localhost:3000/catalog)
- อุปกรณ์/เบราว์เซอร์มีกล้อง หรือมีบาร์โค้ดทดสอบ (พิมพ์ฉลาก/หน้าจอ)
- อ่าน contracts: [contracts/ui-contracts.md](./contracts/ui-contracts.md)

## Setup

```bash
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `/catalog`

## Scenarios

### S1 — MVP: สแกนใส่ช่องบาร์โค้ด (เพิ่มสินค้าใหม่)

1. กดเพิ่มสินค้าใหม่
2. ตรวจว่าแถวป้ายกำกับ "บาร์โค้ดสินค้า" มีปุ่ม **สแกนบาร์โค้ด** คู่กับ **สร้างบาร์โค้ดอัตโนมัติ**
3. กด **สแกนบาร์โค้ด** → Modal กล้องเปิด
4. ส่องบาร์โค้ดให้กล้องอ่านสำเร็จ
5. **คาดหวัง**: Modal ปิดเอง, ช่องบาร์โค้ดมีค่ารหัสที่อ่านได้, ฟอร์มยังเปิดอยู่, ไม่ถูกพาไป `/pos`

### S2 — แก้ไขสินค้า

1. เปิดแก้ไขสินค้าที่มีอยู่
2. กด **สแกนบาร์โค้ด** แล้วอ่านสำเร็จ
3. **คาดหวัง**: ค่าในช่องถูกแทนที่; หากเคยเป็นบาร์โค้ดร้าน ป้ายภายในควรหาย (isInternalBarcode = false)

### S3 — ร่วมกับวิธีกรอกอื่น

1. พิมพ์บาร์โค้ดด้วยมือ → ค่ายังอยู่
2. กดสร้างบาร์โค้ดอัตโนมัติ → ได้ค่ารหัสตามเดิม
3. กดสแกนแล้วอ่านสำเร็จ → ค่าถูกแทนด้วยรหัสจากกล้อง

### S4 — ยกเลิก / กล้องใช้ไม่ได้

1. กรอกชื่อสินค้าไว้ก่อน แล้วเปิดสแกน แล้วกดปิดโดยยังไม่อ่าน
2. **คาดหวัง**: ชื่อและช่องบาร์โค้ดไม่เปลี่ยน
3. จำลองปฏิเสธสิทธิ์กล้อง (หรืออุปกรณ์ไม่มีกล้อง)
4. **คาดหวัง**: ข้อความไทยแจ้งปัญหา; ปิดแล้วพิมพ์บาร์โค้ดมือได้

### S5 — Regression POS

1. เปิด `/pos` แล้วใช้ปุ่มสแกน Navbar / Modal สแกนขายตามเดิม
2. **คาดหวัง**: continuous scan / ตัวนับ / เพิ่มตะกร้ายังทำงานเหมือนเดิม

## Build sanity

```bash
npm run lint
npx tsc --noEmit

```

## Pass criteria

- S1–S4 ผ่านตามคาดหวังใน spec
- S5 ไม่ regress POS
- ไม่มี API ใหม่ถูกเรียกตอนกดสแกนในฟอร์มแคตตาล็อก
